# Moonotes 0.6.2-beta.3 — реакция через Cloudflare и глобальный чат

Экспериментальный, **не развёрнутый автоматически** сервис для реакций игроков. Он хранится отдельно от `worker/` (сервиса 7TV) и **не меняет** его R2, API или старые сборки Moonotes.

## Схема

1. Игрок A открывает `/moonotes → Настройки → Эмоты+ → Сетевые реакции (beta)` и нажимает **Создать комнату**.
2. A копирует **случайный 32-символьный шестнадцатеричный код** и передаёт его доверенному другу **вне Minecraft-публичного чата**.
3. Игрок B на **том же Minecraft-сервере и по тому же адресу подключения** открывает окно, вводит код и нажимает **Присоединиться**.
4. Каждый клиент вычисляет SHA-256 от **локального идентификатора сервера** и секретного кода; Cloudflare получает **только хеш комнаты**, а не адрес сервера или исходный код.
5. При ПКМ по эмоту мод отправляет через WebSocket ID/имя эмота. Cloudflare Durable Object пересылает его другим участникам комнаты. Получатель проверяет UUID + ник по реально видимому игроку в своём Minecraft-мире и показывает реакцию над ним.
6. Если нужного изображения нет в локальном кеше, клиент пытается загрузить его с 7TV через существующий безопасный `ImageDownloader`, иначе временно показывает текстовый плейсхолдер.
7. При выходе из Minecraft-сервера соединение закрывается. Поведение локального ПКМ сохраняется даже если внешний сервис недоступен.

**Другая версия Moonotes должна поддерживать протокол**; обычные игроки без Moonotes и сервер Minecraft ничего устанавливать не обязаны.

## Безопасность и приватность

Это **только предварительный тест с доверенными участниками**. Владение кодом комнаты **НЕ подтверждает владение игровым ником или UUID**: на offline-auth сервере любой приглашённый с известным кодом потенциально может выдавать себя за другого игрока. Проверка имени и UUID на клиенте снижает количество ложных отображений, но НЕ устраняет эту угрозу. Для общедоступной релизной версии требуется отдельная проверка личности или подтверждение каждого приглашённого игрока.

- Подключение только после явного действия игрока. При каждом новом подключении к Minecraft-серверу надо заново создать или ввести код. Код хранится только в оперативной памяти клиента, не сохраняется в файл.
- Worker не принимает и не сохраняет чат, координаты, историю сообщений, токены и изображения; передаёт только UUID, ник, ID и имя 7TV-эмота. IP участников виден инфраструктуре Cloudflare в рамках обычного сетевого соединения.
- Используется общий секрет комнаты (128 бит) и `wss://`; код не помещается в URL, URL содержит только вычисленный хеш.
- Не более 12 соединений на комнату, не более одной реакции за 800 мс и восьми реакций за 10 секунд на подключение. При перегрузке кадры отклоняются.
- Реакции эфемерные; офлайновой очереди или сохранения событий нет.
- Только отдельно развёрнутый Cloudflare Workers + SQLite-backed Durable Objects. R2-манифесты 7TV остаются нетронутыми.

## Развёртывание (только владелец аккаунта)

Нужен Cloudflare-аккаунт с возможностью создать Durable Objects, Node.js 24 и Wrangler. Выполняется **вручную** из папки `reactions-worker/`:

```powershell
npx wrangler login
npx wrangler deploy
```

Выполнение `deploy` создаст отдельный Worker `moonotes-reactions` и Durable Object namespace `ReactionRoom`. Настройка `new_sqlite_classes` нужна для нового пространства DO. **Не** деплойте это через старый `worker/01-DEPLOY.cmd`. GitHub Actions только собирает и проверяет код; не публикует Worker.

**Проверьте адрес после публикации:** тестовый JAR ожидает ровно `wss://moonotes-reactions.thefreelom.workers.dev`. Этот адрес будет работать только если Worker развёрнут в Cloudflare-аккаунте с таким `workers.dev`-поддоменом. Сейчас исходники **не подтверждают**, что Worker уже развёрнут.

Для локальной отладки можно запустить `npx wrangler dev`, а клиенту разрешён только loopback-override `-Dmoonotes.reactions.endpoint=ws://127.0.0.1:8787`. Произвольные незащищённые внешние адреса отклоняются.

## Проверки

```powershell
node --check src/index.mjs
node --check src/protocol.mjs
node --test test/protocol.test.mjs
```

А оба мода собираются из корня:

```powershell
.\network\gradlew.bat -p .\network clean build
```

**Сценарий проверки в игре:** открыть один Paper/vanilla multiplayer-сервер с двух Windows-клиентов, поставить `moonotes-0.4.2.jar` + `moonotes-network-0.6.2-beta.3.jar` + Streamotes, соединить обоих по секретному коду, дождаться «Подключено» и «Других участников: 1», затем нажать G → ПКМ на первом. Второй должен увидеть эмот над **первым**, при условии что оба клиента видят игрока в мире. Проверить обратное направление, F5, отключение, повтор после перезахода и отсутствие сообщений в обычном чате.

### Ограничения beta.1

- Публичной сетевой идентификации игрока нет; это не версия для незнакомых участников.
- Отдельный Worker нужно развёртывать вручную.
- Для совместной комнаты оба игрока должны использовать одинаковый исходный серверный адрес (если один использует IP, а другой домен, комнаты будут различаться).
- Загрузка чужого эмота может занять время, поэтому первая реакция иногда отображается как текст.
- Внешний сервис может быть ограничен квотами Cloudflare.

## Глобальный чат: !WW и настоящие !эмоты

В beta.2 и beta.3 исправляется конфликт между локальным префиксом глобального чата и эмотами с именем, начинающимся на `!`. При наборе и отображении полученных сообщений:

- `!WW` остаётся **неизменным текстом сообщения**, но визуально распознаётся как глобальный префикс `!` и эмот `WW`, если `!WW` как отдельный эмот не существует.
- `!vanish` и `!setgame` остаются цельными эмотами, если именно эти полные названия зарегистрированы в Streamotes.
- `! WW` продолжает работать как прежде.
- Настраиваемый префикс глобального чата из Moonotes учитывается и в предпросмотре ввода, и в отображении чата.
- При выборе `WW` через Tab в черновике `!WW` ведущий `!` сохраняется, лишний пробел между `!` и `WW` не вставляется.
- Обычные команды и исходный текст, отправляемый на сервер, не переписываются.

**Изменились оба JAR:** для этой проверки используй `moonotes-0.4.2.jar` и `moonotes-network-0.6.2-beta.3.jar` из **одного** GitHub Actions artifact. Не устанавливай одновременно старые и новые версии Moonotes. Cloudflare Worker для реакций остаётся совместимым: повторно развёртывать его из-за этого исправления не требуется.

Проверка: `!WW`, `! WW`, `!vanish`, `!setgame` при наборе и в отправленных сообщениях; убедиться, что игровой сервер по-прежнему получает привычный префикс глобального чата. Миксин отображения чата пока не проходил игровой тест.

### Дополнительное исправление beta.3

Beta.2 корректно определяла `!WW` в подсказках, но отрисовка могла пропускать эмот из-за того, что проверка реестра зависела от состояния отдельного адаптера Network. Beta.3 проверяет имя напрямую в реестре установленного Streamotes. Рендер чата также распознаёт `!` и `WW`, даже когда серверный плагин разбивает их на разные цветные компоненты. Добавлены регрессионные тесты `StreamotesRegistryDirectLookupCheck` и `GlobalChatRichTextCheck`.

**Внимание:** автоматическая компиляция не заменяет реальную проверку в Minecraft: проверяй `!WW` при наборе и после отправки; обычный `WW`, `! WW`, `!vanish` и `!setgame` должны остаться рабочими. Если визуал всё ещё не отображается, нужны скриншот и факт, появляется ли проблема при наборе, в полученном сообщении или в обоих местах.
