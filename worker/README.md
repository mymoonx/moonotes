# Moonotes R2 0.5.3

Обновление существующего Worker `moonotes-emotes` для нескольких каталогов 7TV.
Канал добавляется в GUI по Twitch-нику; набор — по его 7TV ID. Worker получает
список и сохраняет его в прежнем приватном R2 `moonotes-emotes`.

## Установка обновления

1. Распакуй эту папку целиком. Нужен Node.js **22.12 или новее** и доступ к своему
   аккаунту Cloudflare через Wrangler.
2. Открой PowerShell в этой папке и выполни:

   ```powershell
   npm ci
   npx wrangler login
   npm test
   npx wrangler deploy
   ```

   Если вход уже выполнен, `wrangler login` повторять не нужно. В Windows можно
   запустить `01-DEPLOY.cmd`: он установит зависимости, проверит код и выполнит
   развёртывание. При отсутствии входа Wrangler предложит авторизацию.
3. Открой `https://moonotes-emotes.thefreelom.workers.dev/health`.
   У обновлённого Worker указаны `version: "0.5.3"`, `bucketBound: true` и
   возможность `canonical-cdn-ids`.

`wrangler.toml` сохраняет имя Worker `moonotes-emotes`, привязку `EMOTES` и имя
бакета `moonotes-emotes`. Обновление кода не удаляет существующие изображения
или каталог v0kky. Создавать новый бакет и повторять загрузку всех файлов не нужно.

Подготовленный архив сам ничего не публикует. Развёртывание происходит только
после запуска указанной команды у владельца аккаунта.

## Исправление загрузки изображений в 0.5.3

CDN 7TV перенаправляет адрес с маленькими буквами в ID на адрес с заглавными
буквами. Прежний Worker запрещал переходы и показывал HTTP 502 для новых файлов.
Готовые файлы из R2 продолжали работать, поэтому ошибка проявлялась при загрузке
второго каталога.

Worker теперь сразу запрашивает канонический адрес 7TV. Старые 24-символьные
ID преобразуются по опубликованному правилу 7TV. Ключи R2 сохраняются прежними:
повторно загружать рабочие файлы или удалять кеш не нужно. Неожиданные переходы
на другие адреса по-прежнему не выполняются. Ошибки изображений дополнительно
различают ответ 7TV, сбой соединения и ошибку записи R2.

Для исправления альтернативного источника **нужно обновить этот Worker**, даже
если клиентский мод уже обновлён. После развёртывания открой `/health`, проверь
версию 0.5.3, затем в Moonotes нажми «Загрузить недостающие» для нужного каталога.
Если 7TV блокируется на компьютере, сам клиент использует Cloudflare в режиме
«Авто»; проверка сертификатов TLS остаётся включённой.

Проблемный эмот `TEATIMEMEGAZOOMAAAAAA` проверен отдельно: реальный CDN возвращал
308 для lowercase-ID и 200 для канонического URL. Исправленная функция Worker
получила WebP размером 30 588 байт. Это проверка кода и текущего публичного CDN,
а не подтверждение, что владелец уже опубликовал обновление Worker.

## Поиск каталогов, сохранённый из 0.5.2

Поиск Twitch-ника выполняется через `POST https://7tv.io/v3/gql`, затем берётся
текущий набор конкретного Twitch-подключения через `/v3/users/twitch/<id>`.
Старый поиск `GET /v3/users?query=...` не используется: при проверке 23 ноября
2026 года он вернул HTTP 404. Простое совпадение имени профиля 7TV не принимается.

Ошибки содержат безопасные поля `error`, `stage`, `upstreamStatus` и `version`.
Клиент показывает источник, этап и точный HTTP-статус; произвольный текст
ответов и внутренние сообщения Cloudflare в GUI не попадают.

Сохраняются псевдонимы одного эмота, признаки анимации и наложения. Поэтому число
названий в каталоге может быть больше числа файлов. Пустой действующий набор
не считается сетевой ошибкой. Отсутствующий набор возвращает отдельную ошибку.

## Что происходит после обновления

В GUI Moonotes можно добавить Twitch-канал или набор 7TV. Для первого запроса
нового каталога Worker должен получить данные от 7TV. Уже сохранённый каталог
возвращается из R2 сразу; после 12 часов его обновление запускается в фоне.
Если 7TV временно недоступен, прежний список остаётся доступен.

Если новый каталог ещё не попадал в R2, а 7TV недоступен и мод не может получить
его напрямую, остаётся импорт JSON или предварительная загрузка с ПК владельца.
Ошибка первого запроса не создаёт пустой каталог и не перезаписывает старый.
Настоящий пустой набор 7TV с корректным ID и `emotes: []` допускается.

Worker 0.5.3 поддерживает новые каналы и набор по ID через альтернативный источник.
Существующий путь v0kky остаётся совместим со старыми версиями мода. Обновление
Worker само по себе не исправляет регистрацию эмотов в Minecraft — это делает
патч дополнения Moonotes Network.

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Версия, возможности, наличие привязки R2 |
| `GET /v1/7tv/channel/v0kky` | Каталог Twitch-канала; вместо v0kky допустим другой ник |
| `GET /v1/7tv/set/<id>` | Каталог по ID набора 7TV |
| `GET /v1/7tv/<id>/2x.webp` | Изображение; также доступны 1x, 3x и 4x |
| `HEAD` на этих путях | Проверка наличия; не запускает скачивание или обновление |

Пример формата каталога:

```json
{
  "schemaVersion": 1,
  "channel": "v0kky",
  "setId": "01kycqs3b86r95r13aawjsbvt7",
  "name": "Название набора",
  "fetchedAt": "2026-11-23T00:00:00.000Z",
  "count": 1,
  "emotes": [
    {"id": "01f6mzgcng000255k4x1k7nthr", "name": "Alias", "animated": true, "zeroWidth": false}
  ]
}
```

Значения выше иллюстрируют формат; текущий состав набора запрашивается из 7TV.
У каталога по ID поле `channel` отсутствует. Сохраняется имя эмота именно в наборе
(его псевдоним), а не глобальное имя. Два псевдонима одного изображения остаются
двумя записями каталога, но файл изображения хранится один раз.

Ключи R2:

- `manifests/7tv/<twitch-login>.json` — прежний ключ v0kky сохранён.
- `manifests/7tv/channels/<twitch-login>.json` — прежние дополнительные каталоги 0.5.1 тоже читаются; при GET обновляются в основной ключ, исходная копия не удаляется.
- `manifests/7tv/sets/<set-id>.json` — отдельные наборы.
- `7tv/<emote-id>/<size>.webp` — прежние ключи изображений.

## Необязательная предварительная загрузка

Обычно изображения заполняют R2 по мере запросов клиентов. Для предварительной
загрузки всех отсутствующих файлов:

```powershell
node sync-r2.mjs --channel v0kky
node sync-r2.mjs --channel another_channel
node sync-r2.mjs --set 01KYCQS3B86R95R13AAWJSBVT7
```

Запуск `02-PREFETCH-ALL.cmd` сохраняет прежнее поведение: канал v0kky.
Готовые объекты проверяются через HEAD и пропускаются. Неуспешные объекты попадут
в `<канал>-sync-report.json` или `set-<id>-sync-report.json`; повторный запуск
докачает отсутствующие. Счётчик файлов учитывает уникальные изображения, а не
псевдонимы. Одновременно выполняется до трёх запросов.

Если Worker не получил каталог, скрипт пробует 7TV напрямую с этого ПК. При
блокировке может потребоваться VPN. Полученный каталог загружается в R2 через
авторизованный Wrangler; токен не передаётся клиентам Minecraft. Существующий
`03-UPLOAD-MANIFEST.cmd` позволяет вручную загрузить `v0kky-manifest.json`.

## Проверки и ограничения

Worker принимает только GET/HEAD по фиксированным маршрутам. Внешние запросы
идут только к HTTPS-адресам `7tv.io` и `cdn.7tv.app`; перенаправления запрещены.
Twitch-канал определяется по точному имени связанного Twitch-аккаунта. Совпадение
одного лишь имени профиля 7TV недостаточно.

Ответ 7TV ограничен 8 МиБ для исходных метаданных, каталог — 2000 записями и
1 МиБ после нормализации, WebP — 3 МиБ. Ограничение проверяется во время чтения,
включая ответы без Content-Length. Таймер охватывает заголовки и тело запроса;
для определения канала оба запроса делят один срок в 12 секунд. HTML вместо
изображения, неверный RIFF/WebP и некорректные записи не сохраняются. Полная
проверка декодирования выполняется на стороне мода; Worker не декодирует картинки.

Изображения кешируются в R2 и в региональном кеше Cloudflare. Повторные запросы
одного объекта в одном экземпляре Worker не запускают параллельные загрузки;
при ограничении 7TV соблюдается Retry-After. Это не глобальный лимит запросов
и не отменяет учёт операций Cloudflare. Общий лимит для публичного сервиса при
необходимости настраивается в аккаунте Cloudflare.

В коде нет сбора клиентских идентификаторов, чата, IP-адресов, загрузки отчётов
или публичного административного API. Стандартные сетевые данные и настройки
журналов Cloudflare управляются отдельно владельцем аккаунта.

`npm test` выполняет 30 локальных проверок с подменёнными fetch/R2: маршруты,
псевдонимы, флаги наложения, прежний кеш, сбой 7TV, лимиты, таймаут тела,
Retry-After, HEAD, кеш Cloudflare, канонические URL новых и старых ID и безопасные ошибки. Эти проверки не являются
проверкой развёрнутого Worker или доступности сервиса у конкретного провайдера.

## Необязательная проверка живого API

```powershell
npm run check:live -- v0kky
npm run check:live -- --image 01f5z4b9700008kdxa2tjqbngw
```

Первая команда только читает каталог 7TV и выводит число названий и уникальных
файлов. Вторая читает одно изображение тем же кодом, что используется в Worker,
проверяет WebP и выводит размер и SHA-256. Они не записывают ничего в R2,
не публикуют Worker и не входят в `npm test`.
Доступность сети на компьютере пользователя проверяется отдельно от локальных
регрессионных тестов. При блокировке 7TV команда может не пройти без VPN.
