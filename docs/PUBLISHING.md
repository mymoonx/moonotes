# Публикация Moonotes

Проект подготовлен как один репозиторий с независимыми компонентами `moonotes/`, `network/` и `worker/`. Исходники модов не объединяются в один JAR.

## Первый репозиторий

Предлагаемое имя: `moonotes`, владелец: `thefreelom`. Видимость выбирает владелец: публичная позволяет пользователям открывать код и скачивать релизы, закрытая ограничивает доступ приглашёнными участниками.

Лицензия для собственного кода пока не назначена; лицензии Gradle Wrapper сохранены. Выбор лицензии остаётся за владельцем проекта и не является техническим условием загрузки исходников или сборки. Этот комплект сам по себе не назначает всему проекту MIT или другую лицензию.

В корень репозитория загружаются файлы из папки `moonotes` подготовленного комплекта. Готовые JAR и релизные ZIP добавляются в раздел Releases; они не нужны в истории исходников.

Если публикуешь через Git с уже созданным пустым репозиторием, из корня подготовленной папки:

```powershell
git init -b main
git add .
git commit -m "Prepare Moonotes 0.5.3 for publication"
git remote add origin https://github.com/thefreelom/moonotes.git
git push -u origin main
```

Команды с адресом выше подходят, только если создан именно этот репозиторий. Не используй принудительный push поверх существующего проекта. Учётные данные вводятся через штатную авторизацию GitHub, не в исходниках и не в чате.

## Проверка Actions

После первого коммита открой Actions → Build and checks. Ожидаются две сборки модов — Windows и Linux — и отдельные проверки Worker. Workflow использует Java 25, Node.js 24, закреплённые версии Actions и права только на чтение содержимого.

Успешные сборки сохраняют устанавливаемые JAR в артефактах. Worker не развёртывается автоматически; ключ Cloudflare для этого workflow не требуется.

## Первый релиз

Предлагаемый тег: `v0.5.3`. Название: **Moonotes 0.5.3 — каталоги, группы и уведомления**.

Текст описания подготовлен в [releases/v0.5.3.md](releases/v0.5.3.md). Для релиза подготовлены основной `moonotes-0.4.1.jar`, `moonotes-network-0.5.3.jar`, архив Worker и `SHA256SUMS.txt`. Автор проекта уже подтвердил работу этих файлов в игре; происхождение сборок описано в [VERIFICATION.md](VERIFICATION.md).

Перед публикацией сопоставь тег с текущим исходным коммитом. Не помечай проверки Actions успешными до завершения реального запуска. Если выкладываешь новые JAR из Actions вместо ранее проверенных, обнови хеши и сведения о происхождении.

## Дальнейшие обновления

Сохраняй структуру папок, обновляй номер версии только изменённого компонента и описывай изменения в CHANGELOG. Worker, основной Moonotes и Network могут иметь разные версии. Изображения, игровые настройки, журналы и ключи доступа остаются вне Git-истории.
